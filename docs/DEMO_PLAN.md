## 0. 一句话

8~12 分钟内跑通：**出据点 → 打怪 → 捡残响 → 回据点炼化 → 凑够条件 → 突破 → 存档**。

验收只看一件事：这条链接不接得上，不看好不好玩。

## 2. 对原案的三处修正

### 修正 1：经验数值算不通（重要）

原案：突破需经验 ≥100；打手 10×2 + 异兽 10 + 精英 30 + 任务 20 = **80**。**差 20 点，闭环卡死。**

推荐补法（三选一，见待确认项）：让**炼化残响也给经验**。

| 来源 | 经验 |
|---|---|
| 打手 ×2 | 20 |
| 异兽 ×1 | 10 |
| 精英 ×1 | 30 |
| 任务完成 | 20 |
| **炼化残响 ×1** | **20** |
| 合计 | **100** ✓ |

素材正好够：异兽掉 1 + 精英掉 1 = **2** ✓
残响也够：1+1+1+2 = 5，炼化用掉 1 ✓

### 修正 2：存档结构要按 JsonUtility 的限制改

原案用了 `enemyStates: {}` 字典和 `playerPosition: [0,0]` 数组。
Unity 的 `JsonUtility` **不支持 Dictionary**，得改成列表：

```json
{
  "playerName": "无名",
  "hp": 100,
  "maxHp": 100,
  "exp": 0,
  "realm": "觉醒者",
  "abilities": ["a_burn"],
  "resonanceCount": 0,
  "breakthroughMaterials": 0,
  "questState": "未接取",
  "questKills": 0,
  "enemyStates": [ { "id": "e_attacker_1", "dead": true } ],
  "sceneId": "overworld",
  "playerX": 26.19,
  "playerY": 19.09
}
```

`playerPosition` 拆成两个 float，`enemyStates` 用列表，**新增 `sceneId` 记录当前在哪个场景**。
其余和原案一致。

### 修正 3：安全屋 = 独立场景（已拍板）

原案写的是"区域用交互点区分，不做复杂场景切换"。**这一条已改为做场景切换**：
安全屋是**单独一张室内图**，走到街上的门口按 E 传送过去，室内走到门口再回街上。

这打破了原案"不多地图"的技术边界，代价是实打实的：

| 新增要做的 | 说明 |
|---|---|
| 多场景注册表 | 现在 `SceneData` 只读死一个 `Data/scene.json`，要改成场景列表 |
| 世界重建 | 切场景时要销毁旧世界、重建背景/碰撞/敌人/互动点 |
| 门/传送点 | 一个能指定"去哪张图、落在哪个坐标"的交互类型 |
| 存档加场景字段 | 读档要回到正确的场景和位置 |
| **一张室内图** | 目前没有，先用程序生成的占位室内图，你有素材随时替换 |

好处：据点有"进门"的仪式感，战斗区和安全区彻底分开，不会在街上误触据点功能。

## 3. 系统设计

### 3.0 场景与传送（新增，因安全屋改为独立场景）

| 项 | 设计 |
|---|---|
| 场景注册 | `Data/scenes.json` 列出所有场景 id，每个 id 对应一份 `scene_<id>.json` + 一张背景图 + 一份遮罩 |
| 现有 `scene.json` | 改名为 `overworld` 场景；新增 `safehouse` 场景 |
| 切场景 | `WorldRoot.Rebuild(sceneId, spawnImageX, spawnImageY)`：销毁旧世界 → 加载新场景 → 重建背景/碰撞/敌人/互动点 → 把玩家放到指定坐标 |
| 传送 | `InteractionDef.action = "travel"`，`targetScene` + `targetImageX/Y` |
| 死亡 | 同样走 `travel` 到 safehouse 的固定坐标 |
| 存档 | 新增 `sceneId`；读档先切场景再放玩家 |

**室内图**：目前没有素材，**我用程序生成一张占位室内图**（地面/墙/家具的色块），
你之后给 AI 生成的室内像素画，覆盖同名文件 + 重算遮罩就能换掉。

### 3.1 战斗（新增）

| 项 | 设计 |
|---|---|
| 普攻键 | **J**（E 已被交互占用） |
| 判定 | 玩家朝向偏移 0.55 世界单位处，半径 0.75 的圆形判定 |
| 伤害 | 12（突破后 +3） |
| 冷却 | 0.5 秒 |
| 受击表现 | 角色 SpriteRenderer 闪白 0.12 秒 |
| 玩家死亡 | HP≤0 → 回出生点（据点），HP 回满，掉落清空（不进背包） |

不做：连招、闪避、弹反、技能栏、多段攻击。

### 3.2 敌人（新增）

三种，全部**配置化**在 `enemies.json`：

```json
{ "enemies": [
  { "id": "attacker", "name": "异能者打手", "hp": 40, "damage": 8,
    "speed": 2.2, "attackRange": 0.9, "attackInterval": 1.2,
    "exp": 10, "resonance": 1, "materials": 0, "sprite": "enemy_attacker" },
  { "id": "beast", "name": "异兽", "hp": 30, "damage": 6,
    "speed": 2.8, "attackRange": 0.8, "attackInterval": 1.0,
    "exp": 10, "resonance": 1, "materials": 1, "sprite": "enemy_beast" },
  { "id": "elite", "name": "精英异能者", "hp": 80, "damage": 12,
    "speed": 1.8, "attackRange": 1.0, "attackInterval": 1.8,
    "exp": 30, "resonance": 2, "materials": 1, "sprite": "enemy_elite" }
] }
```

**站位**写在 `interactables.json` 同级的 `enemies_spawn.json`（或直接合并），按地图像素坐标摆，
固定刷新，死亡后不再出现（状态进存档）。

AI 极简：直线朝玩家移动 → 距离 ≤ attackRange 就按间隔攻击 → 被遮罩挡住就停下（不做绕路）。

**形象**：没有素材，我程序生成 3 张 32×48 占位像素（打手=冷灰人形、异兽=暗红团块、精英=紫黑人形带高光）。

### 3.3 掉落与拾取（新增）

- 敌人死亡 → 在尸体位置生成掉落物（残响/素材）
- 掉落物是场景里的实体，带一点上下浮动
- 玩家进入 1.0 单位内**自动拾取**，HUD 计数 +1，飘一行日志
- 不做背包格子、不做容量、不做掉落概率（固定掉）

### 3.4 据点 5 个交互点（扩展现有系统）

现有 `InteractionDef` 只有 `eventId`（播文本）。**加一个 `action` 字段**，让同一个系统承载不同功能：

```json
{ "id": "i_refine", "name": "炼化台", "action": "refine", ... }
```

| action | 交互点 | 行为 |
|---|---|---|
| `event` | 情报板/普通物件 | 播 `events.json` 里的事件（现状保持不变） |
| `refine` | 炼化台 | 消耗 1 残响 → 弹三选一面板 → 获得能力 +20 经验 |
| `rest` | 休整床 | HP 回满 |
| `storage` | 物资箱 | 弹出面板显示残响/素材数量 |
| `breakthrough` | 突破点 | 条件检查 → 满足则突破 |
| `quest` | 情报板 | 接任务 / 查看进度 |

这样**不用为每个功能写一套新系统**，也不会破坏已有的 5 个互动点。

### 3.5 任务（新增）

单条主线，状态机三态：`未接取` → `进行中` → `已完成`

- 情报板接取 → 状态变"进行中"
- 击杀打手时 `questKills++`，达到 2 就变"已完成"，给 20 经验
- HUD 左上角追踪文字：`凝核之前　清剿旧街区打手 1/2`

不做多任务、不做分支、不做对话树。

### 3.6 境界与突破（新增）

| 项 | 值 |
|---|---|
| 初境界 | 觉醒者 |
| 突破后 | 凝核者 |
| 条件 | exp ≥ 100 **且** 炼化次数 ≥ 1 **且** 素材 ≥ 2 |
| 表现 | 弹面板逐条打勾显示三个条件，全绿才亮"突破"按钮 |
| 奖励 | HP 上限 +20，普攻 +3 |
| 收尾 | 自动存档 + "Demo 闭环完成"提示 |

不做心魔、不做多阶段、不做天赋树。

### 3.7 UI（补齐）

现有 HUD（ESC 呼出）里补：

- HP 条（不是数字，是条）
- 经验条 + 数值
- 当前境界
- 残响 ×N　素材 ×N
- 任务追踪（HUD 收起时也常驻左上角，小字）
- 交互提示（已有）
- 炼化三选一面板（复用事件面板结构）
- 突破条件面板
- 受击时屏幕红闪（可选，M4 再加）

## 4. 里程碑

### M0 —— 先证明现状能跑（**阻塞项**）

- 关掉 Unity 编辑器，跑 `RunAll` + `CaptureWorldPreview`
- 修掉暴露出来的问题
- **验收**：自检 0 失败，截图能看到街道 + 主角 + 互动标记

### M1 —— 多场景架构 + 安全屋室内

- `scenes.json` 场景注册表（overworld / safehouse）
- `SceneData` 改成按 id 加载；存档加 `sceneId`
- 世界重建流程（切场景时销毁旧世界重新搭）
- 程序生成一张占位室内图 + 它的碰撞遮罩
- 街上加「安全屋门」，室内加「出口」，双向传送
- **验收**：能从街上进门、从室内出门，位置和碰撞都对；存档记住当前场景

### M2 —— 战斗

- `GameState` 扩展：realm / resonance / materials / questState / enemyStates / playerPosition
- 敌人实体 + 极简 AI + 血条 + 受击闪白 + 死亡
- 玩家普攻（J）+ 冷却 + 受击 + 死亡回安全屋（走场景传送）
- **验收**：能打死 1 个敌人；玩家被打掉血；死了自动回安全屋

### M3 —— 掉落与拾取

- 掉落物实体 + 自动拾取 + HUD 计数
- `enemies.json` 三种敌人配置化 + 固定刷新
- **验收**：杀 2 打手 + 1 异兽，HUD 显示 残响 3 / 素材 1 / 经验 30

### M4 —— 据点经营

- `InteractionDef.action` 扩展
- 炼化台三选一（灼击 / 铁躯 / 预判）+ 20 经验
- 情报板接任务 + 追踪
- 休整床回血、物资箱查数量
- **验收**：能炼化出能力并生效，能接任务并看到 1/2 进度

### M5 —— 突破与收尾

- 境界 + 突破条件检查 + 突破面板
- 属性提升 + 自动存档 + Demo 完成提示
- 玩家位置/敌人状态存档
- **验收**：完整跑一遍 8~12 分钟，退出重进进度还在

### M6 —— 验收调优

- 补提示文案、调数值、修阻塞
- **验收**：原案第 15 节的 9 条全部满足

## 7. 风险

| 风险 | 应对 |
|---|---|
| 现状没验证过 | M0 先跑一遍，暴露问题再往下建 |
| **多场景让存档和世界重建变复杂** | 这是你选"独立室内图"带来的。M1 一轮只做场景切换，不掺战斗，出问题好定位 |
| 室内图没素材 | 先用程序生成的占位图，结构上支持随时替换 |
| 战斗手感只能靠调 | 伤害/冷却/判定范围全部提成 Inspector 可见字段 |
| 敌人会卡在树和花坛上 | 接受（直线追击），卡住了也不会卡死玩家 |
| 8~12 分钟是估算 | M5 实测，超时就降敌人 HP 或提高伤害 |
| 占位美术难看 | 明确接受，这不是本轮目标 |
